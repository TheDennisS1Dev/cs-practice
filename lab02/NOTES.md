Объяснение о различиях Git и GitHub:

Git — это локальная система контроля версий: она хранит историю изменений кода, позволяет работать с ветками и откатываться к старым версиям. Устанавливается на компьютер. 
GitHub — это облачная платформа поверх Git: хранит репозитории, помогает команде работать вместе (пул‑реквесты, code review), автоматизирует процессы и служит площадкой для обмена проектами. 

Главное отличие: Git — инструмент для управления версиями, GitHub — сервис для хранения и совместной работы с кодом на базе Git.

Сравнение двух команд (git diff и git diff --staged):

git diff и git diff --staged сравнивают разные состояния файлов в Git — это помогает видеть, что именно попадёт в коммит.

git diff (до git add)
Сравнивает рабочую директорию (ваши текущие файлы на диске) с индексом (staging area).
Показывает изменения, которые ещё не добавлены в подготовку к коммиту.

Что увидите: правки, которые вы сделали, но ещё не «застейдили» через git add.

git diff --staged (после git add)
Сравнивает индекс (staging area) с последним коммитом.
Показывает изменения, которые уже готовы к коммиту — то, что реально уйдёт в историю при git commit.

Использованные команды:

git status - Показывает список файлов и их статус — без деталей изменений, просто «кто где».
git diff - Сравнивает рабочую директорию с индексом.
Показывает текстовые изменения (строки «минус» и «плюс») только для тех файлов, которые ещё не добавлены через git add. Для уже застейдженных файлов ничего не покажет.
git diff --staged (раньше писали git diff —cached) - Сравнивает индекс с последним коммитом.
Показывает изменения, которые уже готовы к коммиту — то, что реально уйдёт в историю при git commit.

Что такое ветка, что происходит с ней при новом коммите и что делает слияние.
Ветка — это указатель на коммит, отдельная линия разработки (например, для новой функции или исправления бага).
При новом коммите ветка автоматически сдвигается вперёд — теперь она ссылается на этот свежий коммит.
Слияние (git merge) — переносит изменения из одной ветки в другую: Git «пришивает» историю коммитов и (если нет конфликтов) создаёт коммит слияния. Если в одних и тех же файлах меняли одни строки — возникает конфликт, его надо исправить вручную.
